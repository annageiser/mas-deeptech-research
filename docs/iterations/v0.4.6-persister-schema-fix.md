# v0.4.6 — Hermes persister: align with `public.signals` schema

**Date**: 2026-06-10
**Trigger**: Anna's smoke-verification SQL hit `column "collected_at" does not exist`. Discovery cascaded into finding that the persister I shipped in v0.4.4 was broken for the actual insert path — only the "0 signals from agent" path had been exercised so far, which masked the bug.

## What was broken

`systems/hermes/scripts/persist_signals.py` (v0.4.4) built signal rows like:

```python
{
    "actor_slug": ...,
    "system": "hermes",
    "title": ..., "summary": ..., "evidence_quote": ...,
    "source_url": ..., "source_name": ...,
    "published_at": ...,            # ← wrong column name
    "confidence": ..., "content_hash": ...,
    "collected_at": now,            # ← column doesn't exist
}
```

vs. the actual `public.signals` schema in `systems/masfactory/.../persistence/schema.sql`:

```sql
create table public.signals (
    id uuid primary key default gen_random_uuid(),
    run_id        uuid not null references public.runs(id) on delete cascade,
    actor_slug    text not null references public.actors(slug),
    system        text not null check (system in ('masfactory', 'hermes')),
    source_kind   text not null check (source_kind in ('arxiv','website','swissreg','manual','news')),
    source_url    text not null,
    title         text not null,
    summary       text not null,
    evidence_quote text not null,
    dimension     text not null,
    is_technical  boolean not null,
    confidence    double precision not null,
    observed_at   timestamptz,            -- ← what the agent's `published_at` should map to
    inserted_at   timestamptz not null default now(),
    embedding     vector(768),
    content_hash  text not null,
    -- v0.4.x add-columns: signal_type, dimension_legacy, stakeholder,
    --                     human_validated, validator_notes, validated_by,
    --                     validated_at, prompt_version
    unique (actor_slug, source_url, content_hash)
);
```

Three NOT-NULL columns the v0.4.4 persister omitted:
- `run_id` — FK to `public.runs`. Every signal must belong to a run.
- `source_kind` — required CHECK-constrained enum.
- `is_technical` — required boolean.

Plus the two field-name mismatches above (`published_at` → `observed_at`, no `collected_at`).

## Why we hadn't hit it yet

Through v0.4.5, every smoke run returned `signals: []` from the agent because the search-provider key was missing (v0.4.5 fixed that wiring). The persister's `if not rows: return 0` branch fired every time, and the bad row payload was never actually POSTed. As soon as Firecrawl/Tavily started returning real signals, the next persist call would have crashed with a 23502 NOT-NULL violation on `run_id`.

Anna's exploratory SQL — `max(collected_at)` — failed first because she queried the column name I made up in the iteration-doc snippet (not in the live schema). Same root cause, surfaced via SQL instead of an upsert.

## What v0.4.6 ships

**`systems/hermes/scripts/persist_signals.py`** — rewritten with three modes:

```
persist_signals.py --create-run
    → INSERT into public.runs (system='hermes', status='running')
    → print the new UUID to stdout (nothing else)

persist_signals.py --close-run --run-id <uuid> --status ok|error
                   [--error-message <text>]
    → PATCH the run row (finished_at = now, status, optional error_message)

persist_signals.py --actor-slug <slug> --stdin-file <path> --run-id <uuid>
    → parse agent stdout, validate, UPSERT signals tied to the run
    → print the count of NEW rows inserted (one int, no chatter)
```

Row payload now matches the schema exactly:
- `run_id` passed in by the shell loop
- `source_kind="news"` (hermes-agent web research output)
- `is_technical=False` (default; agents discover non-technical signals)
- `observed_at` (was `published_at`)
- `collected_at` removed (use `inserted_at` for "when did this row land")

**`systems/hermes/scripts/collect_all_actors.sh`** — wraps the lifecycle:
1. Create run row at start, capture UUID
2. EXIT trap closes the run with status=error if interrupted
3. Per-actor: invoke agent → persist with `--run-id`
4. Close run with status=ok if no actors failed, else status=error with a summary message

Also adds a **soft preflight check**: if no search-provider env var is set, warn but don't fail — the agent will degrade to `Tools: 0` and produce 0 signals (the v0.4.5 finding). Better to log "WARN: no search-provider key" than have Anna chase another 0-signal mystery.

**`docker-compose.yml`** — image bump `0.2.1 → 0.2.2`. No env-block change.

## Updated SQL queries (for `docs/reproducibility.md` and ad-hoc checks)

Anything that used `collected_at` is wrong. Use these instead:

```sql
-- Most recent hermes activity
SELECT count(*) AS rows,
       max(inserted_at) AS most_recent_insert,
       count(DISTINCT actor_slug) AS actors_with_signals
FROM signals
WHERE system='hermes'
  AND inserted_at > now() - interval '1 hour';

-- Per-run summary
SELECT r.id, r.system, r.started_at, r.finished_at, r.status,
       count(s.id) AS signals,
       count(DISTINCT s.actor_slug) AS actors
FROM runs r
LEFT JOIN signals s ON s.run_id = r.id
WHERE r.system='hermes'
GROUP BY r.id
ORDER BY r.started_at DESC
LIMIT 10;

-- Sample signals from the latest hermes run
SELECT actor_slug, signal_type, dimension, title, source_url, confidence
FROM signals
WHERE system='hermes'
ORDER BY inserted_at DESC
LIMIT 20;
```

In Supabase, after the smoke:

```sql
-- Did a runs row land + close?
SELECT id, started_at, finished_at, status, config_snapshot
FROM runs WHERE system='hermes' ORDER BY started_at DESC LIMIT 3;

-- How many signals did this smoke produce?
SELECT count(*) FROM signals
WHERE system='hermes' AND inserted_at > now() - interval '15 minutes';
```
