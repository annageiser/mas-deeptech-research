# v0.4.23 — bge-reranker cross-encoder pre-filter (System A)

**Date**: 2026-06-12
**Closes**: task #127

## Why this exists

The Extractor → Classifier pipeline already produces good candidate
signals, but it sometimes surfaces signals about an actor's *non-quantum*
activity — a hit appeared because the actor's name shows up on a press
page for an unrelated topic. The LLM Critic catches some of these, but
pays a Chat Completions call per batch to do it.

A cross-encoder relevance score answers the cheap version of the same
question:

> Is this evidence really about [actor]'s quantum-computing activity?

The dense embedding we already compute (`BAAI/bge-base-en-v1.5`) is a
bi-encoder — fast, but only approximately compares meaning. A
*cross*-encoder scores a (query, doc) pair jointly. ~5-10× slower per
pair, dramatically more accurate at relevance ranking, and zero LLM
tokens.

## What ships

### New module `masfactory_system/reranker.py`

Wraps `fastembed.TextCrossEncoder`. Env-gated singleton (same pattern
as `embedding.py`):

```
MASF_RERANKER=1                      turn the pre-filter on (off by default)
MASF_RERANKER_MODEL=<hf-model-id>    override model (default: Xenova/ms-marco-MiniLM-L-6-v2)
MASF_RERANKER_THRESHOLD=<float>      drop below score (default 0.0 = score only)
```

Why default to `Xenova/ms-marco-MiniLM-L-6-v2` not `BAAI/bge-reranker-base`?
The MS-MARCO model is ~67MB and runs ~3× faster while still beating dense
similarity at the relevance task. For thesis-grade accuracy, swap to
`BAAI/bge-reranker-base` (~280MB) via `MASF_RERANKER_MODEL`.

Helpers:
- `is_enabled() -> bool`
- `model_name() -> str`
- `threshold() -> float` — clamped to [-10, 10] so a typo in .env doesn't
  silently drop every signal
- `score_pairs(query, docs) -> list[float] | None` — `None` ⇒ "skip,
  keep everything"
- `compose_actor_query(actor)` → "`{name} quantum computing activity
  ({category})`"
- `compose_signal_doc(signal)` → title + evidence_quote + summary
  (dimension intentionally omitted — the cross-encoder should judge raw
  evidence, not the LLM's label)

### New CustomNode `agents/reranker_prefilter.py`

```
prepare-actor → extractor → classifier → reranker-prefilter → critic → accumulate-actor
                                         ^^^^^^^^^^^^^^^^^^
                                         new (always inserted, pass-through when off)
```

When `MASF_RERANKER=0` (the default), the node is a pure pass-through.
The graph layout is therefore stable across the two modes — switching
the env var doesn't reshape the graph at build time.

When on:
1. Look up the current actor in `attrs.actor_pool`.
2. Compose a relevance query via `compose_actor_query`.
3. Compose docs via `compose_signal_doc`.
4. Score the (query, doc) pairs.
5. Annotate each signal with `reranker_score` (float, rounded to 4 dp).
6. Drop signals with `score < threshold`.
7. Append drops to the `dropped_reranker` accumulator (audited by
   Persistence as `dropped_reranker.json`).

If scoring fails (model didn't load, ONNX runtime issue), the node
passes through unchanged — recall wins over precision at this stage.

### Wired into the graph

`graph.py`:
- Adds `RerankerPreFilterNode` to the per-actor Loop in `_build_critic_chain`
  for all three critic modes (single / consensus / consensus+debate).
- Adds `dropped_reranker: []` to `WORKFLOW_ATTRIBUTES` and to the
  `ActorLoopNode`'s pull_keys / push_keys / loopback edge.

`agents/persistence.py`:
- Writes `dropped_reranker.json` to the per-run audit folder when the
  accumulator is non-empty.

### Tests

`tests/test_reranker.py` covers:
- `is_enabled()` truthy/falsy parsing
- `threshold()` default, parsing, fallback-on-typo, clamping
- `score_pairs` returns None when disabled / empty inputs
- `compose_actor_query` includes name + humanised category, falls back
  to slug
- `compose_signal_doc` joins title/evidence/summary, excludes
  dimension, handles missing fields

The actual fastembed model round-trip is NOT loaded in unit tests
(280MB / 3s cold-start). Smoke-test on the VPS:

```bash
MASF_RERANKER=1 MASF_RERANKER_THRESHOLD=0 \
  docker compose run --rm masfactory \
  python -m masfactory_system.runner run-once --limit-actors 2
```

Then check `data/raw/runs/<ts>/dropped_reranker.json` and look for
`reranker_score` fields on the persisted signals.

## Calibration

The threshold default `0.0` means **score only, drop nothing**. The
right operational threshold depends on the model and won't be the same
across MS-MARCO and BGE. The thesis-correct path:

1. Run for a week with `MASF_RERANKER=1` and `MASF_RERANKER_THRESHOLD=-10`
   (effectively no filtering).
2. Plot the `reranker_score` distribution from `data/raw/runs/*/signals.json`.
3. Cross-reference against the gold-standard human coding from task
   #102 to pick a threshold that drops ≥80% of false positives without
   losing >5% of true positives.
4. Set `MASF_RERANKER_THRESHOLD=<value>` in `.env` and restart.

## Operator runbook

```bash
git pull
docker compose build masfactory     # nothing new to install — fastembed
                                    # is already in pyproject.toml
docker compose up -d
```

Default behaviour after rebuild: identical to v0.4.22 (reranker is OFF).
To enable scoring-only:

```env
MASF_RERANKER=1
MASF_RERANKER_THRESHOLD=-10
```

To enable filtering after calibration:

```env
MASF_RERANKER=1
MASF_RERANKER_THRESHOLD=0.4
# Optional: stronger but heavier cross-encoder
MASF_RERANKER_MODEL=BAAI/bge-reranker-base
```

## What this is NOT

- **Not** a Critic replacement. The Critic still does multi-agent
  debate, dedup, and quality filtering. The reranker is a cheap *first
  pass* that removes off-topic candidates before the expensive Critic
  sees them.
- **Not** wired into System B. Hermes's CLI agent does its own
  relevance judgement turn-by-turn; cross-encoder pre-filtering
  doesn't fit that paradigm.

## Threat to validity touched

Closes one row in `docs/threats-to-validity.md` (implicit): "off-topic
mentions of an actor's name silently pad the signal count." After
v0.4.23 calibration, off-topic candidates can be quantified (`dropped_reranker.json`)
and optionally filtered.
