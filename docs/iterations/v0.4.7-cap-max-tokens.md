# v0.4.7 — Cap max_tokens to avoid OpenRouter credit-hold rejection

**Date**: 2026-06-10 (same day as v0.4.4/5/6 — the cascade of post-deploy fixes)
**Trigger**: Anna's second smoke after v0.4.6 hit `Error 402 — You requested up to 128000 tokens, but can only afford 110819`. The first smoke ran fine (6 real signals into Supabase). Between the two smokes, her OpenRouter balance dipped below the credit-hold threshold.

## What's happening

Even for OpenRouter's `:free` model tier, every chat-completion request triggers a pre-flight credit reservation:

```
hold = max_tokens × per-token-rate
```

For free models the rate is supposed to be zero, but OpenRouter still enforces a minimum-balance check before letting the request through — partly to prevent abuse, partly because the auxiliary call paths (vision, web_extract summarisation, etc.) can route to paid sub-models. So even though the configured chat model is `nvidia/nemotron-nano-9b-v2:free`, OpenRouter rejects the request if the user's balance can't notionally cover `max_tokens` worth of paid output.

The upstream hermes-agent's default `max_tokens` is "let the model use its full native ceiling." For Nemotron Nano that's 128k — enormous, useless for our JSON-output skill, and the exact cause of Anna's 402.

## What v0.4.7 ships

A two-line edit in `systems/hermes/config/cli-config.yaml`:

```yaml
model:
  default: "nvidia/nemotron-nano-9b-v2:free"
  provider: "openrouter"
  base_url: "https://openrouter.ai/api/v1"

  # NEW: cap output and context so OpenRouter doesn't reject for credit-hold
  max_tokens: 4096
  context_length: 32768
```

`max_tokens: 4096` is generous for our skill's JSON output (the longest plausible response is a list of 6-10 signals × ~300 tokens each ≈ 1800 tokens). `context_length: 32768` caps the total turn so compression triggers at 16k (the 50% threshold from `compression.threshold` in the same file) — which keeps long search histories from costing more than they need to.

No `.env` change, no docker-compose change beyond an image bump (`0.2.2 → 0.2.3`). The config file is bind-mounted into the volume at first boot; the seed-hook only copies if the destination is missing, so existing volumes need a manual nudge — see Anna's recovery sequence below.

## Why this didn't show up in the first smoke

Two reasons:
1. Anna's OpenRouter balance was higher 8 hours earlier. The first run consumed enough credit-hold reservations (even if the actual settled cost was low) to drop her under the 128k threshold for run 2.
2. OpenRouter's rate-limit pages mention that `:free` models still require a non-zero balance once accumulated free-tier daily limits are exhausted, which she may have crossed during the first 6-signal run.

Either way: capping `max_tokens` makes the agent's per-call hold ~32× smaller, so a minimal balance covers many more requests, and short bursts of activity don't accidentally trip the threshold.

## Anna's recovery sequence

```bash
# On the VPS
cd /opt/mas-deeptech-research
git pull

# The config in $HERMES_HOME (the volume) is what the agent actually reads.
# Our seed-hook only installs the default config if config.yaml is missing,
# so we need to either (a) delete it so the new image's config takes hold,
# or (b) edit it in place. Easiest: delete it.
docker run --rm -v mas-deeptech-research_hermes_state:/data alpine \
  rm -f /data/config.yaml
# On next container start, seed-hermes-home.sh re-copies the v0.4.7 config.

# Rebuild wrapper (image bump only, scripts unchanged)
docker compose build hermes
docker images | grep mas-deeptech-research/hermes
# expect: mas-deeptech-research/hermes  0.2.3

# Smoke — 3 actors, 60d window
tmux new -s hermes -d || tmux attach -t hermes
HERMES_LIMIT_ACTORS=3 HERMES_LOOKBACK_DAYS=60 docker compose run --rm hermes
# Detach from tmux: Ctrl-B then D
```

## Belt-and-braces

If the cap alone isn't enough (e.g., the auxiliary `web_extract` summarisation model is routing to a paid endpoint), the second lever is just to **top up OpenRouter credits**: $5 at https://openrouter.ai/settings/credits unblocks weeks of free-tier-with-cap usage. Worth doing on day-of regardless — for a defended thesis you don't want the production cron randomly failing at 05:00 because OpenRouter pre-auth thresholds shifted.
