# v0.4.24 — Sentiment score per signal (C.4)

**Date**: 2026-06-12
**Closes**: task #117

## Why this exists

Every signal carries a `dimension` (what kind of signal) and a
`signal_type` (Ehrenthal bucket), but no axis for *how the signal
reads*. A funding round announced after a competitor's down-round
reads very differently from one announced alongside a layoff, and the
ecosystem-level swing is visible in tone.

A sentiment column lets the thesis ask:

- Do `legitimacy` signals skew positive while `future_trajectory`
  signals carry roadmap uncertainty?
- Does System B's signal mix tilt more positive than System A's?
- When defense flags fire, is the surrounding tone defensive (negative)
  or boastful (positive)?

## Why VADER, not an LLM call

VADER (Hutto & Gilbert 2014) is a lexicon-based scorer tuned on
social-media + news-style English. We use evidence_quote + summary as
the input text.

- **Cheap**: ~1ms per signal on CPU. No model download, no API call.
- **Citable**: well-established academic reference for the thesis
  evaluation chapter.
- **Cross-system parity**: both A and B use the IDENTICAL lexicon +
  composition + thresholds so any sentiment difference between systems
  comes from *what they collect*, not from *how they score*.

LLM-based sentiment was considered and rejected: extra OpenRouter
tokens on every cron tick, model-version drift breaks longitudinal
analysis, free-tier rate limits.

## Schema (run on Supabase once)

```sql
alter table public.signals add column if not exists sentiment_score real;
alter table public.signals add column if not exists sentiment_label text;
create index if not exists signals_sentiment_label_idx
    on public.signals (sentiment_label);
```

Both columns nullable. Pre-v0.4.24 rows stay NULL — the dashboard treats
NULL as "no sentiment" rather than backfilling with a stale lexicon
pass (you can choose to backfill later via a one-off script).

## What ships

### Modules

- `systems/masfactory/masfactory_system/sentiment.py`
  - `is_enabled()` — default **ON**. Disable with `MASF_SENTIMENT=0`.
  - `compose_sentiment_text(signal)` → evidence + summary, title omitted.
  - `label_for(score)` → "positive" | "neutral" | "negative" via the
    VADER paper's thresholds (±0.05).
  - `score_signal(signal)` → `(compound, label)` or `None`.
  - Module-level singleton analyzer; lazy fastembed-style load.

- `systems/hermes/scripts/persist_signals.py` (vendored equivalents
  with the SAME lexicon + thresholds + composition):
  - `_sentiment_enabled()` reads `HRM_SENTIMENT`.
  - `_compose_sentiment_text` / `_sentiment_label` / `_score_sentiment`.
  - Same singleton pattern; cross-system parity invariant preserved.

### Wiring

- MASFactory `agents/persistence.py` calls `score_sentiment` per signal,
  passes both values into `SignalRow`. `_signal_to_row` writes them when
  set; legacy rows stay NULL.
- Hermes `persist_signals.py` calls `_score_sentiment` per signal, sets
  `sentiment_score` / `sentiment_label` on the row dict.

### Dependencies

- MASFactory `pyproject.toml`: adds `vaderSentiment>=3.3.2`.
- Hermes `Dockerfile`: adds `uv pip install vaderSentiment>=3.3.2` into
  the upstream venv after the fastembed line.
- `docker-compose.yml`: passes `HRM_SENTIMENT` through to the Hermes
  service. MASFactory inherits via `env_file: [.env]`.

### API + Web

- `api/data_access.signals()` SELECT now includes `sentiment_score,
  sentiment_label`.
- `api.ts` / `types.ts`: `Signal` interface gains both fields (nullable).
- `signals/page.tsx`: new "Sent." column with a coloured chip:
  - green `+` for positive
  - grey `·` for neutral
  - red `−` for negative
  - em-dash for legacy rows where the value is NULL

Hover the chip to see the VADER compound score.

### Tests

`tests/test_sentiment.py` — 12 cases:
- Default-on env handling, explicit-off via 0/false/no/off.
- Composition uses evidence + summary only (title excluded).
- Threshold edges (±0.05 → positive/negative).
- Score returns None when disabled / empty.
- Real-lib smoke test (auto-skipped if vaderSentiment isn't installed).

## Operator runbook

After `git pull` on the VPS:

```bash
# 1. Apply the SQL migration once in the Supabase SQL editor (or via psql)
#    — see the snippet above (or docs/migrations.md § v0.4.24).
# 2. Rebuild the two image roots that gained a new dep.
docker compose build masfactory hermes
docker compose up -d
```

Default behaviour after rebuild: sentiment **on** for new rows.
To opt out:

```env
# in .env
MASF_SENTIMENT=0
HRM_SENTIMENT=0
```

To verify after one cron tick:

```sql
select system, count(*) total,
       count(*) filter (where sentiment_label is not null) scored
from public.signals
where inserted_at > now() - interval '6 hours'
group by system;
```

Both systems should show `scored = total`.

## Historical backfill (v0.4.24e)

`systems/hermes/scripts/backfill_sentiment.py` mirrors the embedding
backfill: pages rows where `sentiment_label IS NULL`, computes the
score on the SAME composition + thresholds as the live persister, and
PATCH-updates via Supabase REST. Idempotent.

```bash
cd /opt/mas-deeptech-research
# Dry-run first to spot-check
docker compose run --rm \
  --entrypoint python hermes \
  /opt/swiss-quantum/scripts/backfill_sentiment.py --dry-run --limit 10

# Both systems in one go
docker compose run --rm \
  --entrypoint python hermes \
  /opt/swiss-quantum/scripts/backfill_sentiment.py

# Per-system if you want to A/B
docker compose run --rm \
  --entrypoint python hermes \
  /opt/swiss-quantum/scripts/backfill_sentiment.py --system hermes
docker compose run --rm \
  --entrypoint python hermes \
  /opt/swiss-quantum/scripts/backfill_sentiment.py --system masfactory
```

Empty-text rows are written as `(0.0, "neutral")` so the filter set
shrinks monotonically — re-running after partial completion always
makes forward progress.

## What this is NOT

- **Not** a new column on `signal_flags` — flags carry the user's
  judgement on accuracy, sentiment is independent.

## Threat to validity touched

Closes one row in `docs/threats-to-validity.md` (implicit): "we can't
account for tone differences between A and B's collection mix." After
v0.4.24, any tone difference is attributable to *what they collected*
(since the scorer is identical) rather than scoring methodology.
