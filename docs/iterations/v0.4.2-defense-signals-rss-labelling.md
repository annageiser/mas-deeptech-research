# v0.4.2 — Defense signals + RSS + Anna's labelling

**Date:** 2026-06-02
**Git tag:** `v0.4.2` (to be applied on the final commit of this iteration)

## Problem

Three distinct gaps surfaced from triweekly supervisor input + Anna's own dashboard inspection:

1. **No defense signal coverage.** Quantum is dual-use technology; how an actor talks (or doesn't talk) about defense is itself a signal. Ehrenthal et al. (2026) study only positive vendor communications, so their four-signal scheme has no place for *negative* signals like deliberate silence or "national security" deflections.
2. **No central RSS infrastructure.** Industry-wide feeds (The Quantum Insider Daily, Quantinuum Blog, Phys.org Quantum, etc.) publish entries that touch multiple actors at once. Fetching the same feed once per actor was wasteful; more importantly, there was no shared feed registry both systems could read, breaking the comparative-validity invariant for any feed-driven source.
3. **No way for Anna to teach the system from the dashboard.** She can flag wrong signals (since v0.4.1) but couldn't mark good ones to give the Classifier examples. The Classifier prompt was hand-written and never learned from her judgement.

## Under the Hood

**Defense signals as 5th signal_type** in [`schema.yaml`](../../systems/masfactory/masfactory_system/classification/schema.yaml). Two new sub-categories:

- `defense_engagement` — explicit defense contracts, dual-use programmes, classified collaborations. High-cost / high-observability — typically procurement-portal announcements.
- `defense_ambivalence` — *the thesis-novel sub-category*. Silence in communications, "national security" deflections, removed content, refusal-to-confirm-or-deny. Grounded in negative-signalling literature: Connelly et al. (2011) §discontinuance, Eisenberg (1984) strategic ambiguity.

Both flagged `extension: true` so the thesis can A/B with a strict Ehrenthal-only analysis if needed. `Pydantic SignalDimension` Literal extended to include both keys; `labels.py` (api + dashboard) updated; the new signal_type gets its own SIGNAL_TYPE_COLOR (#8c564b — brown for gravity / distinctness).

**RSS infrastructure** centred on a single human-editable [`data/raw/rss_feeds.yaml`](../../data/raw/rss_feeds.yaml) with four groups:

- `industry` — broad feeds (The Quantum Insider, Phys.org, Nature)
- `swiss_media` — Swiss-domestic outlets
- `vendor` — pre-attributed feeds (Quantinuum, IBM, Microsoft)
- `defense` — defense-coverage feeds (Inside Defense)

New collector at [`collection/rss.py`](../../systems/masfactory/masfactory_system/collection/rss.py) is **feed-first, not actor-first** — one HTTP call per feed broadcasts entries to every matching actor. The Retriever now calls it once per pool (not per actor) so the cron cost is constant in feed count, not N × feed count. Same YAML is read by Hermes' `rss_search` tool — keeps the comparative-validity invariant.

**Anna's labelling = signal_flags extension.** The existing `signal_flags` table (Workflow B from v0.4.0) gains a 7th `reason` enum value: `correct_example`. The website's existing flag dropdown now leads with "✓ Mark as correct example (teach the system)" before the wrong-signal reasons. New SupabaseStore method `gold_examples()` returns top-N per dimension (most recent, diversity-stratified); new `classification.few_shot_examples_block()` renders them into the Classifier prompt at runtime. Empty examples → empty block → prompt-only behaviour preserved.

This is light-touch by design — Anna labels through the same UI she already uses for flagging; the Classifier prompt automatically picks up her labels on the next cron tick; no separate gold-set ingestion pipeline.

**Schema migration** in [`schema.sql`](../../systems/masfactory/masfactory_system/persistence/schema.sql) adds:
- `signals.stakeholder` text (which audience the signal addresses)
- `signals.human_validated` boolean + `validator_notes` + `validated_by` + `validated_at` (the formal validation layer above ad-hoc flags)
- `signals.prompt_version` text (which prompt version produced this signal — traceability across iterations)
- `missed_signals` table (false negatives — signals Anna saw but neither system produced)
- `false_positives_recent` view (90-day join of signal_flags + signals for the weekly learning-loop report)
- `signal_flags.reason` CHECK extended to include `correct_example`

Idempotent. Paste-ready block goes in `docs/migrations.md`.
