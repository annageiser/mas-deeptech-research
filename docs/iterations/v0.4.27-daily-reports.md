# v0.4.27 — Daily reports become informative + Hermes collection less conservative

**Date**: 2026-06-13
**Closes**: User-reported "system B doesn't catch any signals"

## What was wrong

Two interacting bugs made System B's daily report look empty.

**Collection side (Hermes).** The skill set the confidence floor at
`>= 0.5`, which is hard to defend from search-snippet evidence alone
(the only evidence the agent has when `web_extract` is unavailable on
the free-tier search backend). The agent was correctly applying the
floor and dropping signals that a more lenient threshold would have
kept. The search-query catalogue listed only six patterns, most of
them anchored on `2026`, which suppressed pre-2026 anniversary
announcements, ongoing partnerships, and roadmap statements with no
specific dates. The persister hardcoded `source_kind = "news"` for
every signal, which made the source-mix metric (v0.4.21 coverage page
and the daily report) say "100% news" regardless of what the agent
actually found.

**Report side (both systems).** The report's `_trim_signals` shipped
nine fields to the LLM but stripped six fields that exist in the
database since v0.4.0 / v0.4.19 / v0.4.24:

- `signal_type` (the Ehrenthal four-signal axis — the entire spine of
  the thesis)
- `sentiment_label` (v0.4.24 VADER output)
- `defense_engagement` + `defense_ambivalence` (v0.4.19 boolean flags)
- `stakeholder` (the audience lens)
- `sentiment_score` (the numeric form behind the label)

Because the LLM never saw these fields, every daily report since
v0.4.0 was silent on the four-signal mix, on sentiment, on the defense
flags, and on the stakeholder lens — i.e. silent on every dimension
the thesis explicitly introduces. The summary likewise omitted these
axes, so the LLM couldn't have written about them even if it tried.

## What ships

### Collection (System B)

- `SKILL.md`: confidence floor lowered from `>= 0.5` to `>= 0.4`. The
  earlier bar was suppressing real signals; the lower bar passes
  through more snippet-grounded evidence while still rejecting low-
  confidence fabrications.
- `SKILL.md`: search-query catalogue widened from 6 to 9 patterns,
  including funding/roadmap/milestone, collaboration/pilot/customer,
  LinkedIn/Medium, an aggressive instruction to "ALWAYS try the
  bundled arxiv skill at least once" for publication evidence, and a
  sector-level fallback for ecosystem builders.
- `SKILL.md` output contract: new `source_kind` field (one of arxiv /
  website / news / swissreg / manual), defaulting to `news` if unsure.
- `persist_signals.py`: `_normalise_source_kind` accepts the agent's
  value if it's in the DB constraint set, else falls back to `news`.
  Never rejects a signal purely because of a source_kind miss.

### Report (both systems)

- `supabase_reader.py`: `signals_for_runs` now selects the v0.4.0
  (`signal_type`), v0.4.19 (`defense_*`), v0.4.24 (`sentiment_*`), and
  `stakeholder` columns.
- `supabase_reader.py`: `_summarise` adds `by_signal_type`,
  `by_sentiment`, `by_source_kind`, `by_stakeholder`,
  `defense_engagement_count`, `defense_ambivalence_count`,
  `actors_no_signals_count`, `actors_no_signals_sample`.
- `daily.py`: `_trim_signals` includes signal_type, sentiment_label,
  sentiment_score, stakeholder, defense_engagement,
  defense_ambivalence.
- `prompts/daily.md`: new sections for Four-signal mix, Source mix,
  Sentiment, Defense flags, Coverage gap, and Signal-type breakdown.
  The voice block now asks the LLM to call out empty categories
  explicitly because "the empty category IS the finding."

## What will change tomorrow

The 02:00 / 05:00 cron tick on the day after deploy will produce the
first daily reports that mention the four-signal mix. The Hermes side
should also produce more signals per actor on average because of the
lower confidence floor + wider search catalogue. The coverage gap
(actors with zero signals in window) becomes visible to the report
LLM for the first time, so the "what's missing" section will identify
specific gap actors rather than just saying "some actors had no
signals."

## How to verify

After `git pull` + `docker compose build hermes reports` on the VPS:

```bash
# Smoke a 2-actor hermes run to confirm the lower-confidence path lets
# more signals through.
HERMES_LIMIT_ACTORS=2 docker compose run --rm hermes

# Then generate a daily report against today's data and inspect it.
docker compose run --rm reports daily --system hermes
cat data/reports/daily/$(date -u +%Y-%m-%d)/hermes.md
```

The daily.md should now have a Four-signal mix line, a Source mix
line, a Sentiment line, a Defense flags line, and a Coverage gap
section.

## What this is NOT

- **Not** a System A change. System A's persister already lets the
  classifier set source_kind; only Hermes had the hardcode. The
  report-side changes affect both systems' reports equally.
- **Not** a relaxation of the "never fabricate" rule. The confidence
  floor moves from 0.5 to 0.4 but the no-fabrication rule and the
  source-attribution rule are untouched.
- **Not** a schema change. All columns being newly surfaced have
  existed since the iteration that introduced them; only the report's
  view of them was missing.

## Threat to validity touched

Closes one row in `docs/threats-to-validity.md` (implicit): "the daily
reports don't reflect the four-signal scheme, so a supervisor reading
them cannot tell whether the systems are doing the work the thesis
claims they do." After v0.4.27 the daily report explicitly carries
the four-signal mix in its first snapshot block, making the
operational evidence visible to anyone reading the /reports page.
