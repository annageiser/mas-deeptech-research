# v0.4.38 — Both systems migrated to Nemotron 3 Ultra 550B

**Date:** 2026-06-25
**Closes:** open decision "Nemotron 3 Ultra switch" from `CLEAN_BACKLOG_NO_1.md` (P3 item 26).
**Scope:** all three LLM-using containers (System A, System B, reports).

## What ships

Both producer systems and the daily-report synthesiser now default to:

```
nvidia/nemotron-3-ultra-550b-a55b:free
```

A frontier-class MoE reasoning model (550 B total parameters, 55 B active per
token) served by NVIDIA on OpenRouter's **free** tier. The v0.4.8
free-only policy is preserved. Fallback is also `:free` so the entire
collection stack stays at zero marginal LLM cost.

Selection is configuration-driven through the existing env vars
(`MASF_MODEL_MAIN`, `HERMES_MODEL`, `RPT_MODEL_MAIN`) plus three new ones:

| Env var | Default | Effect |
|---|---|---|
| `HERMES_MODEL_FALLBACK` | `qwen/qwen3-next-80b-a3b-instruct:free` | L3 per-actor retry model |
| `MASF_REASONING_EXCLUDE` | `1` | OpenRouter `reasoning.exclude` on System A + reports |
| `HERMES_REASONING_EXCLUDE` | `1` | Persisted to `runs.config_snapshot` for replay |

The masfactory + reports fallback (`MASF_MODEL_FALLBACK`,
`RPT_MODEL_FALLBACK`) was already configuration-driven and changes from
`meta-llama/llama-3.3-70b-instruct:free` to
`qwen/qwen3-next-80b-a3b-instruct:free` (lower rate-limit pressure on the
free tier).

## Why this is hard — root cause of the "think" issue

Reasoning models like Nemotron 3 Ultra wrap their final answer inside
`<think>...</think>` (or sibling) tags. The pattern is universal across
the family: Nemotron Super 120B (v0.4.30), gpt-oss-120b (v0.4.34) and
now Ultra 550B all exhibit it.

### System B (Hermes upstream CLI)

The `nousresearch/hermes-agent:v2026.6.5` CLI parses the LLM's text
response and looks for the visible answer. Its response-handling chain
was observed empirically on v0.4.30 as:

> Thinking-only response — prefilling to continue → Empty response from model → Returning empty

The parser cannot reliably extract content emitted alongside (or after)
the `<think>` wrapper. Result: agent stdout has no JSON block,
`_extract_json_block()` in `persist_signals.py` returns `None`, the
persister writes `0` new signals — for **every** actor, **every** run.

This was the symptom that ruled Nemotron Super 120B out in v0.4.31 and
gpt-oss-120b out in v0.4.34. The historical workaround (v0.4.36) was
to pick a plain-instruct model (Qwen3 Next 80B) entirely.

### System A (masfactory)

System A is less exposed: the Instructor-backed structured-output layer
tolerates some leading non-JSON content, and the Classifier prompt
elicits a JSON object the parser can locate even when surrounded by
prose. But reasoning blocks STILL inflate output tokens — burning the
provider-side `:free` quota faster and pushing closer to the per-actor
context floor — and occasionally confuse the Critic when reasoning
trailers leak after the structured payload.

### Reports

The `reports_system/openrouter.py` wrapper takes
`response.choices[0].message.content` verbatim and writes it to the
daily markdown file. v0.4.36 added a regex strip for `<think>` blocks
to catch the legacy case; v0.4.38 widens the strip to six tag families
and adds a dangling-opener heuristic.

## Chosen solution — three-layer defence

We do not "solve" the root cause (we can't patch upstream Hermes).
Instead we ensure the reasoning wrapper never survives end-to-end.

### Layer 1 — Server-side reasoning suppression

OpenRouter accepts a top-level body field that tells the provider to
drop reasoning tokens before returning the response. The shape:

```json
{
  "reasoning": { "exclude": true }
}
```

Reference: <https://openrouter.ai/docs/use-cases/reasoning-tokens>.

Wiring:

- **System A** — `systems/masfactory/masfactory_system/model.py` adds
  `extra_body={"reasoning": {"exclude": True}}` to every chat-completion
  call via the OpenAI SDK. The Failover wrapper applies it before
  delegating to the parent's `invoke()`, so both primary and fallback
  benefit.
- **Reports** — `systems/reports/reports_system/openrouter.py` adds
  the same `extra_body` to `chat()`.
- **System B** — `systems/hermes/config/cli-config.yaml` carries the
  field under `model:`. Whether the upstream Hermes CLI forwards it to
  OpenRouter is opaque (no published schema); if ignored, L2 catches
  the residual case.

Cost: zero. Latency: zero. Reliability: depends on a third-party API
honouring an extra body field — best-effort.

### Layer 2 — Client-side sanitisation (System B)

`systems/hermes/scripts/persist_signals.py` gains a
`_strip_reasoning_artefacts()` helper that runs over agent stdout
BEFORE `_extract_json_block()`. Two passes:

1. **Balanced** — strips `<think|thinking|reasoning|thought|analysis|scratchpad>...</...>` blocks, case-insensitive, multi-line.
2. **Dangling** — when the cleaned text still starts with one of the
   openers (model was truncated mid-reasoning), strips up to the first
   `{` / `[` / ```` ``` ```` so the JSON block stays intact.

When agent stdout contains no reasoning markers, this is a no-op (cheap
substring check before the regex pass).

Same widening applied to `reports_system/openrouter.py`'s
`_strip_reasoning_tags()`.

Cost: ~µs per persist call. Latency: zero. Reliability: deterministic
— catches every reasoning-wrapper variant the model has emitted in
our observations.

### Layer 3 — Model-level fallback (System B)

`systems/hermes/scripts/collect_all_actors.sh` retries a single actor
with `$HERMES_MODEL_FALLBACK` when the primary either errors out or
returns zero parseable signals after L2 sanitisation. The default
fallback is `qwen/qwen3-next-80b-a3b-instruct:free` — a plain-instruct
free model with no reasoning wrapper, so the retry path always
produces something usable even if (a) the Nemotron call hits a
free-tier rate limit, (b) OpenRouter rotates the underlying provider
to one that does not support tool-calling, or (c) L1+L2 jointly miss
a new reasoning-wrapper variant we have not seen.

The `USED_MODEL` for accepted signals is printed in the cron banner
(`[collect_all_actors] ✓ <slug> — N new signals (model=<id>)`) so the
operator can spot when the primary is silently degrading to fallback.

Cost: doubles wall time + tokens for affected actors (both free, so
the monetary cost stays zero). Latency: up to 600 s per affected
actor (timeout). Reliability: catches everything the other two layers
miss.

## Trade-offs

| Aspect | v0.4.36 (Qwen3 Next 80B) | v0.4.38 (Nemotron 3 Ultra 550B :free) |
|---|---|---|
| Model class | 80B-class MoE, plain instruct | 550B-class MoE, reasoning |
| OpenRouter tier | `:free` | `:free` (free-only policy preserved) |
| Token efficiency | Good (no reasoning overhead) | Lower (reasoning tokens consumed even when excluded server-side) |
| Classification quality (a priori) | 80B-tier | 550B-tier — expected lift on edge cases |
| Reasoning robustness | Not needed | Three-layer defence required |
| Comparison-validity invariant | Held (both A+B same model) | Held (both A+B same model) |
| Free-tier failure modes | Rate limit on popular slugs | Rate limit / provider rotation → fallback to Qwen3 Next via L3 |
| Reproducibility surface | model + tool_status in config_snapshot | + model_fallback + reasoning_exclude in config_snapshot |

## Threats to validity touched

- The model swap creates a "v0.4.36 window" and a "v0.4.38 window"
  inside the evaluation period. Per `docs/pre-registration.md` §7
  (acceptable operational deviations), this is a documented departure
  and must be flagged in thesis §4.1.4. The pre-reg metrics (H1–H5)
  still compute on `system IN ('masfactory', 'hermes')` regardless of
  which model the rows came from — `runs.config_snapshot.model`
  identifies the model per row so the evaluation harness can split
  numbers cleanly.
- Comparison-validity invariant preserved: both systems run the same
  model, same provider, same reasoning-suppression setting. Any
  observed difference is attributable to architecture, not the LLM.
- Free-tier dependency: `:free` models on OpenRouter can be rotated,
  rate-limited, or moved to `:paid` at the provider's discretion (the
  v0.4.31 / v0.4.32 history under `collect_all_actors.sh` documents
  three such instances in a single week). L3 fallback prevents a
  complete blackout but a long Nemotron outage would silently degrade
  every System B run to Qwen3 Next results — operators must monitor
  the model breakdown in `/api/compare`'s `per_system.model_counts`.

## Deployment

1. **Update `.env` on the VPS** — confirm `MASF_MODEL_MAIN`,
   `HERMES_MODEL`, `HERMES_MODEL_FALLBACK` from the new `.env.example`.
   `OPENROUTER_API_KEY` does not need paid credit (the primary is on
   the `:free` tier), but the account must be in good standing — free
   models require the `data_collection` opt-in setting that is already
   covered by the cli-config.yaml comment block.
2. **Rebuild all four containers** — `docker compose build masfactory hermes reports api`. (api doesn't change but rebuild keeps the manifest consistent.)
3. **Smoke test** —

   ```bash
   docker compose run --rm \
       -e HERMES_LIMIT_ACTORS=3 \
       -e HERMES_LOOKBACK_DAYS=60 \
       hermes
   ```

   Expected log lines:

   - `[collect_all_actors] paid search backend detected (web_extract enabled)` (or `ddgs`)
   - `[training_context_preflight] ...`
   - `[collect_all_actors] ▶ <slug>`
   - `[collect_all_actors] ✓ <slug> — N new signals (model=nvidia/nemotron-3-ultra-550b-a55b:free)`

   If you see a `↻ <slug> — retry with fallback` line, the primary
   returned zero parseable signals for that actor; investigate
   `*.stderr.txt` to find out whether L1 or L2 should have caught it.

4. **Verify Supabase persistence** —

   ```sql
   select id, system, config_snapshot->>'model' as model,
          config_snapshot->>'model_fallback' as model_fallback,
          config_snapshot->>'reasoning_exclude' as reasoning_exclude,
          status, started_at
     from public.runs
    where started_at > now() - interval '1 hour'
    order by started_at desc;
   ```

   Every post-v0.4.38 run should show `model=nvidia/nemotron-3-ultra-550b-a55b:free`,
   `reasoning_exclude=true`. The model the accepted signals came from is
   in the per-row `signals.system` column unchanged (`masfactory` /
   `hermes` — fallback retries still attribute to `hermes`); the model
   IDENTITY for that hermes run is at the run level.

5. **Update thesis §3.4 and §4.1.4** with the new defaults + the
   three-layer defence narrative.

## Backout

To roll back to v0.4.36 behaviour while keeping the v0.4.37 editorial
layer intact:

```
MASF_MODEL_MAIN=qwen/qwen3-next-80b-a3b-instruct:free
HERMES_MODEL=qwen/qwen3-next-80b-a3b-instruct:free
RPT_MODEL_MAIN=qwen/qwen3-next-80b-a3b-instruct:free
MASF_REASONING_EXCLUDE=0
HERMES_REASONING_EXCLUDE=0
```

No code rollback required — env overrides are sufficient. Persister-side
sanitisation remains active (no-op on non-reasoning models).
