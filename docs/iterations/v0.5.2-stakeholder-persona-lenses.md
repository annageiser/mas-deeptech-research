# v0.5.2 — Stakeholder layer: neutral metric taxonomy + persona lenses

**Date:** 2026-07-24
**Git tag:** `v0.5.2`
**Commits in this iteration:** `942cc24..c0a9ea8` (PR #27, PR #28)

## Problem

The dashboard presented a single generic view of the Swiss-quantum signal store. Two things followed from that.

1. A specific stakeholder — investor, researcher, consultant, corporate, or policymaker — had to already know the signalling-theory vocabulary and hand-assemble filters to get to their own answer. There was no entry point framed around a reader's actual question; §3.2 named these stakeholder groups but nothing in the artefact served them differently.
2. The six derived per-actor metrics carried loaded, evaluative names — *Impact*, *Credibility*, *Authority*, *Cheap-talk ratio* — which read as the tool passing judgement on each actor. That conflicts with the thesis's deliberately descriptive scope (Scope & Limitations: structured intelligence and visualisation only, no recommendations).

Symptom a visitor saw: a metrics-heavy table with judgemental column headers and no lens framed for their decision.

## Under the Hood

Two coupled changes, both confined to the display / derivation layer. Neither touches the collection pipeline, the Supabase schema, `scoring.py` formulas, or the A-vs-B comparison invariant, so thesis comparability is untouched.

**1. Neutral metric taxonomy (PR #27, `942cc24`).** Renamed the six derived metrics to neutral names that state what was measured rather than rank the actor:

| Old (loaded) | New (neutral) |
|---|---|
| Impact | Signal Activity Score |
| Credibility | Cost-Weighted Signal Score |
| Cheap-talk ratio | Low-Cost Signal Share |
| Momentum | Signal Trend |
| Diversity | Signal Breadth |
| Authority | Capability–Legitimacy Ratio |

Touched only human-facing strings: `systems/web/src/lib/glossary.ts` (tooltip titles/bodies), `/methodology`, the leaderboard / overview / signalling / actor headers, and `COST_LABEL` in `systems/api/api_app/labels.py`. The `GLOSSARY` lookup keys, the API/DataFrame field names, the DB columns, `schema.yaml`, and every `scoring.py` formula are unchanged — values are byte-for-byte identical. Design decision: rename what a human reads, keep the field keys stable, so nothing in the data contract or scoring can break. The "Breadth" reframing also exposed a stale `/9` denominator on the diversity column (the schema has 19 dimensions), fixed to `/19`.

**2. Persona lenses (PR #28, `71517ec`).** The five §3.2 stakeholder lenses (Competitor folded into consultant + corporate) as a thin presentation layer over the one shared store. A persona is a *lens* — a saved filter, a metric priority order, and a framing question — not a new data source; every page reuses the existing endpoints, so nothing per-persona touches the pipeline.

- **Derived insight API** — `systems/api/api_app/insights.py`: a pure `compute_insights()` re-composes already-collected signals into source-attributed insight templates (`rising`, `narrative_heavy`, `broad_front`, `new_ground`, `funding`, `regulatory`, `coverage_gap`, `concentration`), each tagged and ordered per persona; served at `GET /api/insights?persona=&system=&days=` (route in `main.py`). The pure-function + thin-wrapper split keeps the logic unit-testable without Supabase (4 tests; api suite 34 passed). Insights are descriptive and window-bounded — correlational, never causal, never prescriptive.
- **Persona pages** — `systems/web/src/lib/personas.ts` holds the five-lens config (framing copy, priority neutral metrics, deep-link questions). `/personas` is an index hub; `/personas/[id]` is the detail page: framing + caveat, question deep-links that carry the active `system`/`days`, insight cards with source links, a per-lens ranked leaderboard, and a lens switcher. Unknown id → 404. Nav gains a "Stakeholder lenses" entry.
- Rejected alternative: a topbar persona switcher that mutates the existing pages — less discoverable and riskier to shared views than dedicated additive pages. Rejected PaperBanana (`dwzhu-pku/PaperBanana`) for generated persona visuals — it is an academic-figure generator, not runtime UI, so it would have added heavy dependencies and an external API key for no runtime benefit; native CSS/emoji cards were used instead.

Both shipped through green CI → `main` → the Hostinger VPS (`git pull` + `docker compose build web api` + restart of `api web caddy`). No Supabase migration (the Supabase Preview check skipped). Fixed in passing: a stock-Python `lib/` rule in `.gitignore` was unanchored and silently ignoring new files under `systems/web/src/lib`; added a `!systems/web/src/lib/` negation.

**Deferred** (design depends on it staying out of scope):

- The prescriptive P3 layer — joining the signal store to external market/funding data (share prices, private-funding records, patent-citation graphs) and recommendation-style scores for investment, subsidy, or acquisition targets. This would turn a system that maps a market into one that advises on it; explicitly out of the descriptive thesis scope and left as future work only.
