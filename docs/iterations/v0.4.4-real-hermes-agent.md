## Decisions (with rationale)

### 1. Submodule, not Docker Hub
Upstream doesn't ship versioned Docker Hub tags. SHA-pinned submodule → exact reproducibility for the thesis. Cost: ~113 MB shallow checkout.

### 2. Two-stage build
`hermes-upstream:local` built once by the operator (10-15 min). Our wrapper `mas-deeptech-research/hermes:0.2.0` is a fast layer (<10 s rebuild). Iteration on our skill / entrypoint doesn't trigger the upstream's Node+Playwright+s6 build.

### 3. `hermes chat -q` over `batch_runner.py`
`batch_runner.py` (57 KB) is for training-trajectory generation from JSONL datasets — not a production single-prompt entry. `hermes chat -q "<prompt>"` is the documented non-interactive single-query path. Loop over actors in shell; agent memory accumulates across calls within the same `HERMES_HOME`.

### 4. Toolset = `web + skills` only
Upstream ships `terminal`, `browser` (Playwright), `image_gen`, `tts`, `cronjob`, etc. We disable all of those:
- `terminal` = security risk in unattended cron
- `browser` (Playwright) = ~400 MB and not needed for text scraping
- `image_gen` / `tts` = irrelevant to signal collection

Leaves `web` (search + extract) and `skills` only.

### 5. JSON-block output contract in the skill
Skill enforces a single ```json``` block. `persist_signals.py` extracts the last fenced block (or brace-balanced fallback), validates against the four-signal taxonomy, and upserts. Misformatted output is logged + counted as zero new signals; the run continues.

### 6. Idempotency via `(actor_slug, content_hash)`
`content_hash = sha256(actor_slug | source_url | title)`. Re-running on the same day inserts new signals only when the agent discovers genuinely new (url, title) pairs.

### 7. Hard time budget per actor: 600 s
`timeout 600 hermes chat ...` in the shell wrapper. Combined with `agent.max_turns: 30` and `tool_loop_guardrails.hard_stop_after` in the config, an actor cannot consume more than ~6 min wall time × ~30 turns of model time.

### 8. Comparison-validity invariant preserved
The new `systems/hermes/` (real CLI wrapper) imports **zero** Python from `systems/masfactory/`. The wrapper uses only `httpx` + `pyyaml` (already in the upstream venv). The invariant the pattern impl honoured ("A and B share no Python beyond Supabase schema") still holds.

### 9. Inherit `system='hermes'` namespace
The user explicitly asked for this: pattern-era rows tagged `system='hermes'` stay; the new agent writes to the same tag. No data migration. Downstream readers (API, web, reports, evaluation) need zero changes. The cost: a step-change in `signals.collected_at` at 2026-06-10 separates pre-real-Hermes signals from post-real-Hermes signals. The thesis Chapter 3.5 will use ≥ 2026-06-10 as the "real Hermes" window for the empirical comparison.

### 10. `/opt/swiss-quantum/` inside the image, not `/opt/hermes/`
Upstream's `WORKDIR` is `/opt/hermes`. Putting our additions at the same path would shadow upstream files. Wrapper additions live at `/opt/swiss-quantum/{config.yaml,skills/,scripts/}`. The seed-hook copies skill + config from `/opt/swiss-quantum/` into the volume at `$HERMES_HOME/{skills,config.yaml}` on first boot.

## Risks

- **Build size**: 1.5 GB image. Fine for our VPS (50 GB SSD) but worth flagging in the thesis as a footprint disclosure.
- **Cold-cache cost**: first agent invocation downloads model schemas + warms OpenRouter — budget +2 min on the first actor.
- **Skill discovery**: the agent might decide our skill is too prescriptive and free-style. The output contract forces JSON; the persister rejects non-conforming output silently (logged, counted as zero new signals). Worth a sanity-check on the first run.
- **OpenRouter rate limits**: 40 actors × ~5-10 tool calls each = 200-400 API calls per cron. Free-tier Nemotron should handle it; if not, switch model via `HERMES_MODEL` env override.
- **Submodule SHA drift**: `ba44de06` is current main. Re-pinning to a tagged release (e.g. when upstream cuts `v0.17.0`) is a one-line `.gitmodules` change + `git submodule update`. The thesis can cite the exact SHA the empirical study used.
