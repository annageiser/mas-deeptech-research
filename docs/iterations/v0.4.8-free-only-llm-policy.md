# v0.4.8 — Free-only LLM policy across all auxiliary paths

**Date**: 2026-06-10
**Trigger**: Anna: "the systems are using a non-free llm. change that, it must be a free one."
**Status**: shipped.

## The leak

Until v0.4.7 the Hermes config only pinned the **main turn** model:

```yaml
model:
  default: "nvidia/nemotron-nano-9b-v2:free"
```

But the upstream agent has several **auxiliary** model paths — paths that fire automatically inside the agent loop, separately from the main turn — and these default to `provider: "auto"`. "Auto" picks "best available", which on OpenRouter often means `google/gemini-3-flash-preview` (paid). Once an auxiliary path fired, the credit-hold pre-auth on Anna's account moved against her balance.

The four auxiliary paths in `agent/auxiliary_client.py`:

| Path | When it fires | Default model with `provider: "auto"` |
|---|---|---|
| `vision` | `vision_analyze` tool, browser-screenshot probes | Gemini-Flash via OpenRouter (paid) |
| `web_extract` | every time the agent calls the `web_extract` tool (long-page summarisation) | Gemini-Flash via OpenRouter (paid) |
| `session_search` | searching past sessions when memory is active | Gemini-Flash via OpenRouter (paid) |
| `compression` | when the conversation crosses `compression.threshold` (50% of context) | Gemini-Flash via OpenRouter (paid) |

Our skill drives the agent to call `web_extract` on every relevant URL it finds — so on a 6-signal day, the `web_extract` aux model fires ~6× per actor minimum. That's plausibly where Anna's balance went.

## The fix

`systems/hermes/config/cli-config.yaml` v0.4.8 explicitly pins every auxiliary path to `meta-llama/llama-3.3-70b-instruct:free` on OpenRouter, plus a defensive `provider_routing` block:

```yaml
auxiliary:
  vision:
    provider: "openrouter"
    model: "meta-llama/llama-3.3-70b-instruct:free"
  web_extract:
    provider: "openrouter"
    model: "meta-llama/llama-3.3-70b-instruct:free"
  session_search:
    provider: "openrouter"
    model: "meta-llama/llama-3.3-70b-instruct:free"
  compression:
    provider: "openrouter"
    model: "meta-llama/llama-3.3-70b-instruct:free"

provider_routing:
  require_parameters: true
  data_collection: "deny"
```

Why Llama 3.3 70B for the auxiliaries: it's free on OpenRouter, supports function calling (so it can drive the agent's tool reuse if the main model delegates), and is a known-good summarisation model. Could equally use `nvidia/nemotron-3-super-120b-a12b:free` (what MASFactory uses) — either is fine, both are free.

## What this means for the thesis

A "this entire artefact runs on $0 of LLM spend" claim is now defensible. Chapter 4.1.4 (Threats to validity) can include a positive line:

> Free-tier-only LLM policy: every LLM call (main agent, fallback, auxiliary vision / web-extract / session-search / compression paths) is pinned to an OpenRouter `:free` model slug, with `provider_routing.require_parameters: true` to prevent silent downgrade to non-tool-capable endpoints. The artefact's reproducibility cost is bounded by Firecrawl's 500/month free tier and OpenRouter's free-tier rate limits — both verifiable by inspecting the model-id field of each request in the audit folder.

This also strengthens the cost-comparison angle of Chapter 3.5: with both systems on the same free-tier provider list, the per-system cost difference is entirely a function of how many calls each system makes, not which model variants they pick.
