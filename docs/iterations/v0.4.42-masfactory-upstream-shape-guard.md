# v0.4.42 — masfactory upstream-shape guard (hotfix)

**Date:** 2026-07-02
**Closes:** In-flight production outage — every masfactory cron tick on 2026-07-02 (3/3) crashed at `Persistence._persist`, and 4 of 7 runs over the last 3 days had the same failure signature. No 2026-07-02 daily report was generated for either system because the chained report step depends on a successful collector run.
**Scope:** two Python edits (`agents/loop_nodes.py`, `agents/persistence.py`), 8 unit tests, this doc. No env, no schema, no dep, no container.

## Problem

The 2026-07-02 02:00 CET masfactory cron produced this traceback on every attempt:

```
File "/app/masfactory_system/agents/persistence.py", line 139, in _persist
    a, u = s.get("actor_slug"), s.get("source_url")
AttributeError: 'str' object has no attribute 'get'
```

The Persistence node iterates `surviving` (the list of Critic-accepted signal candidates handed to it by the per-actor loop's `AccumulateActor`) expecting each item to be a `dict`. On 2026-07-02 at least one item in the list arrived as a `str` — specifically, the JSON-encoded representation of the signal dict rather than the parsed dict itself. The v0.4.36 defensive-attribution loop (`for s in surviving: a, u = s.get(...)`) has no shape check and raised on the first non-dict item, killing the whole run before any signals were persisted or any audit was written.

Root cause upstream is under investigation. The two candidate producers are:
1. **Classifier via `instructor`-typed structured output** — the OpenRouter response occasionally contains a `classified` array where individual items are JSON strings instead of parsed objects. On Nemotron 3 Ultra 550B (in production since v0.4.38, 2026-06-25) the pattern coincides with reasoning-token blocks that leak past the v0.4.38 server-side `reasoning.exclude=true` suppression.
2. **`AccumulateActor` in `loop_nodes.py`** — under the same `current_slug` short-circuit path, the accumulator can pass a string signal through the actor-slug guard without recognising the shape violation (line 111 in the pre-hotfix code).

Either way, the fix has to make Persistence robust to what Classifier + Critic + AccumulateActor actually hand it, rather than what the type contract says they should.

## Under the Hood

Two edits, symmetric and additive.

### `masfactory_system/agents/persistence.py`

Before the actor-attribution loop (line 138), each item in `surviving` is now type-checked. If it is:

- a `dict` — passes through unchanged (baseline);
- a `str` that JSON-decodes to a `dict` — the decoded dict is used (the observed root-cause pattern; recovers the signal);
- a `str` that isn't JSON, or a JSON-decoded non-dict, or a non-`str`/non-`dict` — dropped to a new `dropped_upstream_shape.json` audit file with a diagnostic entry (`type`, `parsed_type`, and a truncated `content`/`repr`) so the pattern is inspectable per-run without needing to reproduce it live.

### `masfactory_system/agents/loop_nodes.py`

The same guard is repeated at the earlier failure point in `_accumulate_actor` (line 111). This is deliberately redundant: even in a hypothetical future where the Classifier's JSON envelope changes shape between the loop and Persistence, either guard alone is sufficient to recover. Belt-and-braces here costs eight lines of code, and the two locations serve different diagnostic purposes — the accumulator's guard tells us the drift happened at Classifier time (`iteration_dropped` is per-iteration), while Persistence's guard tells us the drift survived the accumulator's guard (`dropped_upstream_shape.json` is run-wide).

### Fail-open, not fail-closed

Both guards drop offending items and continue, rather than raising. This matches the existing v0.4.36 pattern in Persistence (`dropped_hallucinations.json` for actor-attribution failures) and the pre-reg §6 "what counts as a valid run" definition — a run with zero surviving signals is still a valid run for token-cost accounting. In this hotfix, a run whose Classifier emits 100% junk becomes a `status='ok'` run with `signals=0` and a diagnostic audit; a run where 3 of 5 signals arrive as JSON strings ends up persisting 5 signals with a diagnostic audit noting the pattern.
